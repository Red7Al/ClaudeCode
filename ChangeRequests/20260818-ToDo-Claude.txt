Application Focus - Security
------------------------------------------------------------------------------------------------------------------------------------------------

    * P-10 "Throttling is a good idea, please proceed" -- Brute-force protection on /api/login (SECURITY_RECOMMENDATIONS HIGH #1). The endpoint accepted unlimited password guesses: no per-IP cap, no per-account cap, no lockout, no alert. It matters more than it used to because logins are guessable NAMES rather than emails, the site moved from a random tunnel hostname to a stable public domain, and a successful guess reaches the ORDER path rather than just data. PERSISTED in a new login_attempts table, not in memory: the 2026-07-28 advice ("a small in-memory counter is enough for a single-process app") is void under CGI, where every request is a fresh process, so such a counter counts to one forever and only looks like protection. Two scopes -- (ip, name) for grinding one account, ip alone with a higher ceiling for spraying many usernames. The check runs BEFORE verify() so a locked-out attacker never reaches PBKDF2, which also stops the endpoint being a CPU amplifier. Alerts to #alerts on a lock, because silent throttling lets someone grind for a week unnoticed. FAILS OPEN on a database error, deliberately and pinned by a test: being locked out of your own trading account during a Supabase blip is worse than a brief unthrottled window; revisit if the site ever takes public signups. Six tests run against the real table rather than a mock, since the property under test is cross-process persistence. Commit c79b9fb. Claude. [Completed]
