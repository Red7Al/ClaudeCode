Operations — Change Control

How change requests are captured and tracked

Changes to the platform are captured as change requests and worked through in a controlled way, so there is always a record of what was asked for, what was done and why. The Change Requests tab surfaces this in the application.

01

The change-request files

  • Requests are recorded in dated change-request files (one per batch of requests).
  • Each item carries a priority (P-01 bugs, P-02 queries, P-06 changes, P-10 new functionality, P-12 documentation, and so on).
  • As an item is worked, its status moves through Not Started, In Progress and Completed. The status marker is always the last token on the line so it reads unambiguously.
02

Completion notes

A completed item records what was actually done — the root cause for a bug, the decision taken for a change, the tests that passed — immediately before the final status marker. This is the evidence trail: anyone reading later can see not just that something changed, but why and how it was verified.

Status is updated live: an item is marked In Progress when picked up and Completed only when verified, never in a batch after the fact. This keeps the record trustworthy.
