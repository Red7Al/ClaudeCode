Support — Adding Users

Creating accounts and approving access requests

New accounts are created from the User Management tab (admin only). There are two routes: create an account directly, or approve a request someone has submitted. Both follow the same security model — the account is created without anyone ever setting or seeing the user's real password.

01

Create a user directly

  1. Open User Management and click "+ Add user".
  2. Enter the person's name and email address, and choose the subscription tier. A clearly-invalid email (for example one with a comma or no domain) is rejected here.
  3. Tick Admin and/or Support if they need those roles. Support grants read-only Batch Activity, System Logs and Scheduled Jobs only; it is independent of Admin, so you can set either, both or neither.
  4. Save. The account is created enabled but locked (an unusable random password).
  5. If outbound email is configured, a password-setup email is sent to their address automatically so they can set their own password. If email is not yet configured, use "Set a temporary password" (below) to activate the account instead.
02

Approve an access request

When someone requests access, their request appears at the top of User Management. Approving it creates the account exactly as above — locked and enabled — and, when email is configured, sends the setup email immediately. Reject removes the request.

No admin ever sees or types the user's own password. The account is created locked and the user sets their own credential — from the setup email where email is configured, or by changing the temporary password after their first sign-in.
03

Activating an account when email is not configured

The platform normally emails a setup link so users choose their own password. Until outbound email is switched on, that email cannot be delivered and a new account stays locked. For an account that does NOT hold IG credentials, an admin can set a temporary password directly so the person can sign in.

  1. In User Management, find the account's row and look at the Password Complexity column.
  2. Click "Set temp password". (If the row shows "IG-linked — use email reset" instead, the account has IG credentials and this route is intentionally not available — see the note below.)
  3. Type a password, or click Generate for a strong one, then confirm.
  4. Give that password to the person through a secure channel — a phone call or a direct message, not email. They sign in with it and can change it afterwards.
"Set temp password" is admin only and appears only for accounts with no IG credentials. An IG-linked account can place real trades, so it must use the email-based reset instead; the server enforces this even if the button is bypassed. Once outbound email is configured, this manual step is no longer needed.

Roles at a glance

RoleWhat it can do
UserStandard access to the trading tabs their subscription allows.
SupportRead-only Batch Activity, System Logs and Scheduled Jobs — nothing else admin-only.
AdminFull access, including User Management, Configuration (Admin) and Version History.
