Operations — Other

Odds and ends that keep the platform running

This guide gathers the smaller operational topics that do not need a page of their own but are worth writing down.

01

Secrets and the credential store

  • Service credentials live in the encrypted store (backed by Supabase), not in plain files. The local .env is kept in full only as a cold backup and is not pruned.
  • Every credential the app reads should have a path into the store; a new secret referenced by a workflow but with no import path is a gap to close.
02

Snapshots and data

  • The scanner works from a daily snapshot rebuilt on the web-server machine. Several local-only jobs (such as the scanner-report email) depend on it and must run after it.
  • Supabase backups run daily.
03

Slack notifications

  • Slack posting respects an off switch per channel — every direct poster checks whether the channel is enabled before sending.
04

Where to look when something breaks

SymptomFirst place to look
Site down / errorsSystem Logs — health cards and the error level filter.
A job did not runScheduled Jobs (did GitHub run it?) then Batch Activity (did this platform record it?).
No X postsX Posts and the "Funding X publications" guide.
A user can't sign inUser Management — is the account enabled, resend the reset.
When in doubt, follow the evidence trail top-down: Scheduled Jobs → Batch Activity → System Logs. Each narrows the problem before you change anything.
