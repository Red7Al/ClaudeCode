Operations — User Management

Accounts, roles and subscriptions

User Management is the admin tab for the platform's accounts. It covers creating users, setting roles and subscriptions, enabling or disabling access, and setting a temporary password when needed. Admins always retain access to this tab so they cannot be locked out.

01

Creating accounts

Use "+ Add user" to create an account directly, or approve a pending access request. Either way the account is created locked and enabled; you can set Admin and/or Support at creation. Where outbound email is configured, a password-setup email is sent so the user chooses their own password — no admin ever sets or sees a real one. See the "Support — Adding Users" guide for the step-by-step.

02

Roles

RoleWhat it grants
UserStandard trading access per subscription. This is the default.
SupportIndependent of Admin. Grants read-only Batch Activity, System Logs and Scheduled Jobs only — nothing else admin-only. Set with the Support checkbox, either at creation or on the user's row.
AdminFull access including this tab, Configuration (Admin), Markets (Admin) and Version History. Set with the Admin checkbox.

Admin and Support are independent flags — a person can be one, both or neither. The role is enforced on the server, not just in the interface.

03

Subscriptions

  • The subscription tier (for example Silver / Gold) controls which trading features an account can reach — for instance, Multi-Factor Momentum is a Gold-tier feature.
  • Change a subscription from the user's row; it takes effect on their next load.
04

Temporary passwords

  • When outbound email is not yet configured, the setup email cannot be delivered, so a new account stays locked. The "Set temp password" button in the Password Complexity column lets an admin set a password directly and hand it over securely; the user changes it later.
  • It is offered only for accounts with no IG credentials. IG-linked accounts show "IG-linked — use email reset" instead, because an account that can place real trades must go through the email-based reset; the server enforces this.
  • Once outbound email is switched on, prefer the normal reset flow and this manual step is no longer needed.
05

Enabling and disabling

  • Disabling an account blocks sign-in without deleting anything, so it can be reversed.
  • Where email is configured, a password reset can be re-sent if a user is locked out; otherwise set a temporary password as above.
Deleting or permanently removing account data is a destructive action — prefer disabling. Keep at least one active admin at all times.
