Operations — System Logs

Health at a glance and the recent server log

The System Logs tab is the first place to look when something seems off. It combines live health cards, a searchable log table and clickable charts. It is available to Admin and Support.

01

Health cards

  • Server start time and uptime.
  • Python version and the current snapshot's generated time and record count.
  • Database ping (round-trip in milliseconds) and row counts for the key tables (working orders, X publications, batch activity, activity log, triggers).
  • Whether a snapshot refresh is currently in progress.
02

The log table

The most recent server log records, newest first. Each row carries a timestamp, a level (INFO / WARNING / ERROR), the module that emitted it and the message. Sort by any column.

03

The charts

Four clickable charts sit above the table — by Level, by Module, by Hour and by Month. Clicking a bar filters the table to that slice, and the charts cross-filter each other, so you can narrow to (say) errors, from one module, in one hour.

A red spike on the Level chart is the fastest way to find a problem: click ERROR, then the Module chart shows which component is responsible.
