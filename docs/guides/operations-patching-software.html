Operations — Patching software (e.g. choco)

Keeping the host machine's software current

The web server and its data jobs run on a host machine whose software needs to be kept patched. On Windows this is typically done with Chocolatey (choco). This guide covers the routine safely.

01

Before patching

  • Check nothing critical is mid-run — avoid patching during a snapshot rebuild or a scheduled publication window (see Scheduled Jobs for the timings).
  • Know how to restart the web server afterwards, in case a dependency updated underneath it.
02

Routine update with Chocolatey

  1. Open an elevated (Administrator) PowerShell on the host.
  2. Review what is outdated: choco outdated.
  3. Upgrade all packages: choco upgrade all -y (or name a single package to be conservative).
  4. Restart the web server if Python or a key dependency changed, and confirm the site loads.
03

After patching

  • Open System Logs and confirm the server restarted cleanly and the snapshot count looks right.
  • Check Scheduled Jobs on the next cycle to confirm the automated jobs still run.
Patch one thing at a time when in doubt. Upgrading everything at once is faster but makes it harder to tell which package caused a regression if the site misbehaves afterwards.
