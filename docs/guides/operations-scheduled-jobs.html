Operations — Scheduled Jobs

The automated jobs and their run history

The Scheduled Jobs tab lists the platform's automated jobs and their recent run statistics. It is available to Admin and Support.

01

How the automation runs

Most jobs run as GitHub Actions workflows, triggered on a schedule by cron-job.org. Each job maps to a workflow file; the tab reads that workflow's recent run stats from GitHub — last status, last run time, number of executions and failures.

02

Reading the table

  • Each row is one job, with its schedule (in UTC) and its latest outcome.
  • The charts above the table are multi-select and cross-filter each other; "Recent failures" narrows to jobs that have failed recently.
If two jobs share one workflow file, they will show identical stats even when they run hours apart for different reasons — that reads like a duplicate but is not. Each job that needs its own history should have its own workflow file.
03

A note on local-only jobs

A few jobs cannot run on a GitHub runner because they need files that only exist on the machine running the web server (for example the daily snapshot and the local user list). The daily scanner-report email is one of these — it runs from a local scheduler (such as Windows Task Scheduler) on the web-server machine, after the day's snapshot rebuild, not from the GitHub Actions pipeline.
