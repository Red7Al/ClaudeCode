## 3. Open work, in the order I would take it

### 3.1 `_perf_bars` derived-map store — the only item that moves the real constraint

**Measured** via `egress_report.py` differenced over a 147.9h window from a clean baseline:

```
shape                                   rows    calls    GB/30d   share
_perf_bars (web/report bars)     144,883,741    1,515     66.84   84.4%
everything else                   12,270,056  217,966      5.66    7.1%
other price_history               10,417,631   60,908      4.81    6.1%
TOTAL                                                      79.20   = 15.84x the 5 GB free allowance
```

**Root cause is process churn, not the loop interval.** All six `_perf_bars` call sites are in
`hvf_web/server.py` (the IONOS web tier). `_PB_CACHE`, `_RVOL_CACHE`, `_VOLSCORE_CACHE`,
`_LIVE_VWAP_ATR_CACHE` and `_LIVE_INSTRUMENT_METRICS_CACHE` are all module-level dicts that die with the
CGI worker. Proven: a 22-minute sample with no site traffic showed **zero** `_perf_bars` calls
(`calls=10694` unchanged across 12 samples), so the 10-minute `_perf_warm_loop` is not the driver —
visits that cold-start a worker are, at ~4–6 calls each, ~246/day.

**The agreed approach** (owner endorsed, "if derived are causing issue - store them, rather than
derive"): persist the four **derived maps** — RVOL, VolumeScore, VWAP/ATR, live instrument metrics — to
the IONOS filesystem, keyed on the snapshot's `generated_utc`. Not `price_history` itself: the owner
ruled that out explicitly, "mainly due to performance" on shared hosting.

Why the derived maps are safe where a price mirror is not: the cache key **is** the snapshot generation,
so a stale file cannot be mistaken for current — the key won't match and it recomputes.

**NOT measured yet:** the actual byte size of those four maps. I estimated "a few hundred KB each" from
their shape. Measure before building.

**Before writing any of it**, the owner has asked for its per-request cost stated up front —
connections opened, queries issued — and for the tests to prove that cost. See §5 for why.

   during a refresh is safe.
